Server-side template injection:
- When attacker is able to use native template syntax -> inject malicious payload into template -> executed server-side
- Template engines are designed to generate web page by combine fixed template + volatile data
- Arise when user input is concatenated into templates rather than being passed in as data

Example:
    + Not vuln: $output = $twig->render("Dear {first_name},", array("first_name" => $user.first_name) );
    + Vuln: $output = $twig->render("Dear " . $_GET['name']);

Construct attack:
- Detect:
    + Try fuzzing the template, if exception raised -> injected template syntax is being interpreted by server in some way
- Plaintext context:
    + Most template languages allow to freely input content either by using HTML tags directly or template native syntax
- Code context:
    + Some way of inject malicious data:
        + Example 1:
            code: engine.render("Hello {{"+greeting+"}}", data)
            payload: /?greeting=data.username
                    /?greeting=data.username<tag>
                    /?greeting=data.username}}<tag>
- Identify:
    + https://portswigger.net/web-security/images/template-decision-tree.png

Exploit server-side template injection:
- Read:
    + Learn the basic template syntax
    + Read about the security implications
        + In additional of providing of how to create and use template, it also provide some sort of "Security" section (usually outline all potentially dangerous things people should avoid)
        + This also acting as a cheatsheet for which beaviors you should look for during auditing, as well as how to exploit them
        + Even if no dedicated "Security" section, if built in object or function can pose a security risk, there is almost always warning in the document (may not provide much detail, but at least it should flag it)
        + Example:
            <%= Dir.entries('/') %>
            <%= File.open('/example/arbitrary-file').read %>
    + Look for known exploit:
        + Key aspect of exploiting is being good at finding additional resources online
- Explore:
    + Next step is eplore enviroment and try discover all object which you have access
    + Many template epose "self" or "enviroment" object. act like namespace contain all objects, methods, attributes that supported by template engine
    + If it exist, you can use to generate a list of object that are in scope
    + Example:
        List all var in enviroments in Java template
            ${T(java.lang.System).getenv()}
    + Developer-supplied objects:
        + Website contain both built-in object provided by template and custom, you should pay attention to these non-standard (cuz they may contain sensitive information or exploitable method)
        + If can't RCE, you may still gain access to sensitive data or file path traversal

Create a custom attack:
- Sometimes you will need to construct a custom exploit
- You may find that template engine executes template inside a sandbox, which make exploitation difficult or even impossible
- If there no way to exploit, you should review each function for exploitable behavior
- By working through this process, you may be able to construct a complex attack that even able to exploit more secure target

- Constructing a custom exploit using an object chain:
    + Identify method which you have access ans which object they return
    + Combine your own knowledge and information in document, you will be able to put together a shortlist of object that you want to investigate more thoroughly
    + Example: in Java, you have access to classTool object called $class, document reveal that you can chain the $class.inspect() and $class.type property to obtain references to arbitrary objects
        $class.inspect("java.lang.Runtime").type.getRuntime().exec("bad-stuff-here")
